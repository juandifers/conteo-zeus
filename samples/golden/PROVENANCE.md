# The golden files

Two directories, two different kinds of authority. Confusing them is the one
mistake this file exists to prevent.

| Directory | What it locks | Where the authority comes from |
|---|---|---|
| `zeus-verified/` | **correctness** — these bytes were accepted by Zeus and posted the right balances | Zeus posted it. Nothing generated after the fact can match that. |
| `generated/` | **reproducibility** — that P2 emits what P1 emitted, over a real 298-row catalogue | This repository generated it. It proves nothing about what Zeus does with it. |

Neither is `samples/COMESTIBLES ALMACEN.txt`. That file is the **sheared** one
(`ZEUS_FORMAT.md` §5): 206 rows at `toma = 0`, four columns displaced by a sort
somebody ran in Excel without extending the selection. It is a format reference
and a test fixture for the importer's refusal path. It must never become a
correctness reference.

What the run actually contained:

| `idarticulo` | `nombre` | `existencia` | count taken | `toma` written | `diferencia` written |
|---|---|---|---|---|---|
| `91069` | `PASTA NATURAL DE CEREZA` | `1` | `2` | `2` | `1` |
| `15450` | `PATICA DE CERDO` | `20.5` | `10.5` | `10.5` | `-10` |

One overage, one shortage. Both non-zero, both against a non-zero `existencia`.

**What this evidences** (`ZEUS_FORMAT.md` §7.1, §7.2): Zeus reads `toma`, and a
file carrying a real non-zero `diferencia` posts correctly.

**What it does not evidence**, and the list is longer than the file:

- No zero. Neither row was counted at `0`, so §7.4's "a zero deletes the stock"
  is **not** a property of these bytes. It is recorded in §7.4 from the hotel's
  account of Zeus's behaviour, at a different grade of evidence, and marked so.
- No uncounted row. Both rows carry counts, so `uncountedPolicy: 'existencia'`
  was a no-op here. Part of the verified triple, untested inside it.
- No non-ASCII byte, so CP850 survival is not shown.
- No multi-presentation `codigo`, no `existencia = 0` row, no 11-character
  `costo` truncation, 2 rows rather than 298.
- Nothing about `conteo1` as a target, and nothing about `differenceColumn:
  'zero'`.

`generated/` covers those cases. It covers them against *this repository's own
output*, which is a weaker claim, and the distinction is the whole point of
having two directories.

Two things in this export contradicted `ZEUS_FORMAT.md` v3 and are now recorded
in §7.5: `codigo` `01091426` is **8** characters, not 7, and `Grupo1`/`Grupo2`
carry `nombre`/`presentacion` rather than being empty. The writer re-emits both
from `rawRow` and neither cost a byte — which is the property `verifyWriteBack`
exists to keep true.

## `generated/` — the reproducibility fixture

```
counts.json    idarticulo -> decimal-string quantity
expected.txt   the frozen bytes
```

Generated by this repository from `samples/COMESTIBLES ALMACEN.xls` — the
authoritative `.xls`, not the sheared `.txt` — with the verified triple from
§7.1 and no others:

```
countTargetColumn: 'toma'
uncountedPolicy:   'existencia'
differenceColumn:  'computed'
```

**A generated golden file locks reproducibility, not correctness.** It says that
the writer emits today what it emitted when the file was frozen. It says nothing
about whether those bytes are the *right* bytes: if `writeTxt` were wrong on
2026-08-31, `expected.txt` froze the wrong answer and G1 will defend it
faithfully for as long as nobody notices. Do not read a passing G1 as evidence
that the output is right. The only file in this repository that evidences that
is `zeus-verified/`, and it is two rows long.

Quantities in `counts.json` are **strings**, parsed once at load. A JSON float
would put the value through an IEEE754 double before the test ever sees it,
which is the exact class of error the fixture is meant to catch — `21 - 20.8` is
`0.20000000000000107` in binary and `ZEUS_FORMAT.md` §3's shortest-representation
rule would write that verbatim into the ERP.

### What each count is for

| `idarticulo` | `nombre` | `existencia` | count | Exercises |
|---|---|---|---|---|
| `41` | `PECHUGA DE POLLO` | `20.8` | `21` | an increase — **and** §3's decimal subtraction: `diferencia` must be `0.2`, never `0.20000000000000107` |
| `44` | `HARINA DE TRIGO` | `91` | `85.5` | a decrease, decimal, on a multi-presentation `codigo` |
| `55` | `HUEVOS A` | `10080` | `10079` | a five-digit quantity |
| `67` | `ÑAME` | `0` | `0` | a count on a row whose `existencia` is already `0` — CP850 `Ñ` (`0xA5`) |
| `519` | `ARROZ PARBOLIZADO DOÑA PEPA` | `48` | `47.5` | CP850 `Ñ`; one of two presentations of `0109019`, the other left uncounted |
| `1181` | `PANCETA SV` | `97.5` | `96` | `0103005` has three presentations (`330`, `1181`, `2660`); only this one is counted |
| `1926` | `AJÍ CHIPOTLE AMAZON` | `4` | `0` | **an explicit zero on a non-zero balance** — a shelf found empty. CP850 `Í` (`0xD6`) |
| `1966` | `JAMÓN SELECCIONADO` | `186` | `186` | a count that agrees with the book figure — zero variance is not no-count. CP850 `Ó` (`0xE0`) |

The remaining 290 rows carry no count and are resolved by
`uncountedPolicy: 'existencia'` to `toma = existencia`, `diferencia = 0`.

The resulting file has **32** rows at `toma = 0`: the 31 rows whose `existencia`
is `0` (`ZEUS_FORMAT.md` §9, the fresh-produce rows), plus `1926`, the one
explicit zero. That is the arithmetic **G2** asserts, and §7.4 is why.

## Changing a golden file

`G1` runs in CI on every commit. **When it fails, the default assumption is that
the change is wrong, not that the golden file is stale.**

Updating `generated/expected.txt` requires a commit that touches nothing else
and explains in its message what changed about the output and why that is
correct. A golden file updated in the same commit as the change that broke it is
not a golden file.

`zeus-verified/` is not updatable at all. Its authority is that Zeus posted
exactly those bytes, and regenerating them would destroy the only thing they are
for. If the writer stops reproducing them, the writer is wrong.
